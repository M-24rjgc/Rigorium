# Rigorium 自进化科研平台 — 深度升级路线图

## 总纲
把 Rigorium 从"带科研功能的 Agent 平台"升级为**自进化科研平台**：以「信念驱动的信息增益编排」为核心创新（可发 ICLR/ICML），科研感知路由、PaperStudio 论文工坊、统一能力/插件体系为支柱；**用平台自举写框架论文作为最终验收**。四阶段依次推进，每阶段独立可测、可回滚。

---

## Phase 0 — 基础加固（地基，全部后续工作的前提）

### 0.1 拆分单文件巨兽（只抽代码、不改行为，全程有测试护航）
- `src/agent/loop/AgentLoop.ts`(3268行)：抽出 `recovery/`（截断恢复、空响应重试、LargeFileRepair、熔断器）、`assembly/`（消息组装与 tool-call 收集）、`toolResults/`（配对、指纹、projectToolResults）。主循环只留骨架+编排语义
- `src/router/RouterRuntime.ts`(1334行)：抽 `policy/`（决策策略：sticky、tokenSaver、cache-aware、orchestration 各自独立模块）与 `execution/`（attempt 计划、fallback 链、健康跟踪）
- `src/cli/createLocalGateway.ts`(1537行)：抽 `assembly/`（ProjectRuntime 装配为声明式步骤）
- `desktop/main.mjs`(1168行)：抽出 platform-runtime 已有雏形，继续拆 Zotero broker 配置、verify 模式
- 每个抽取模块配套 `*.node-test.mjs`，跑通 `npm test` 全量后再动下一处

### 0.2 统一双插件系统 → 单一「能力注册表」(Capability Registry)
现状：UI 进程插件（manifest.json+entry+server，`ui/server/utils/plugin-loader.js`）与 TS 数据插件（plugin.json+skills+hooks+routerContributions，`src/extension/plugins/`）互不相通，marketplace 是 stub。
- 定义统一 manifest v2：`{name, displayName, entry?, server?, skills, hooks, routerContributions, capabilities[], commands, settings}` —— UI 插件通过新能力面声明 skills/hooks/router 贡献，由网关统一装载
- 新增 `src/extension/capabilities/CapabilityRegistry.ts`：把各插件 `settings.capabilities` 字符串升级为**机器可检查的能力契约** `{id, accepts, produces, dependsOnCapabilityIds, costModel?, modalityRequirements?}`；注册表在网关进程内，UI 经 RPC 查询
- **能力门控**：ToolRegistry 按能力契约注册/排除工具；编排时 director 依据能力图规划（现有 director 已读 accepts/produces/dependsOn，补齐运行时强制）
- marketplace 从 stub 落地为 git 安装（复用 UI 侧 installPluginFromGit 的成熟逻辑，上移到网关）

### 0.3 路由机制加固（创新前先修地基）
- **全局健康跟踪**：ProviderHealthTracker 从 per-session 提升为 per-provider 全局共享（跨会话记忆降级状态，openreview 403 这类已现问题不再逐会话重试）
- **Sticky 退化**：粘性加 TTL + 质量信号（空响应/连续错误/用户重试次数）触发提前释放
- **Judge 接口化**：`classifyAndRoute` 抽出为 `TierClassifier` 接口（Phase 2 换成不确定性门控实现），本次保持行为不变只留扩展点

**验收**：全量测试绿；行为与重构前一致（对照 router events.jsonl 抽样）；双插件能共存；能力注册表可枚举全部内置能力。

## Phase 1 — 信念驱动编排引擎（核心创新，论文卖点）

### 1.1 Claim 图：工件 DAG → 信念系统
- `src/research/artifacts/types.ts` 新增工件种类：`claim`（主张）、`belief_state`（信念快照）、`evidence_link`（证据-主张边，relation: supports/challenges）
- ArtifactEnvelope 扩展可选字段：`claim?: {statement, confidence, uncertainty, falsificationCondition, status: active|challenged|falsified}`、`evidence?: {links: EvidenceLink[]}`
- 新增 `src/research/claims/`：**信念传播引擎** —— 支持/挑战证据按强度（实验复现>单次观察>引用）聚合，更新置信度；级联失效（现有 `invalidate_descendants` 升级为信念一致的失效，带理由链）

### 1.2 EIG 规划器（替换 director 的启发式决策）
- `src/research/director/` 新增 `eig/`：动作空间 = 科研动作（`run_experiment / literature_search / write_section / review / figure_generation / principle_revision / stop`），每个动作有代价模型（预估 token+时长+资金，从 TokenStatsCollector 学）
- **EIG 估计**：对 claim 图的信念不确定性做"预期不确定性削减量"估计 —— 信息论框架（对齐 PiEvo 的信息定向选择，但作用在 Agent 动作空间而非假设采样空间）
- **选择规则**：单动作 `argmax EIG/cost`；批量并行 = 带互信息惩罚的批量选择（BatchBALD 式去冗余，与现有并行子代理机制对接）
- 保留现有决策词 branch/eliminate/rescan/revise/recover/stop，但由 EIG 计算驱动而非模板
- 不确定的估计在动作后获得真实观测，形成闭环修正（与 1.4 taste 校准共用学习回路）

### 1.3 信念修正回溯（有原则的 backtracking）
- 实验/评审结果写入 claim 图 → 信念传播 → 若核心 claim 被挑战：`invalidate_descendants` 级联 → **重规划**（从修正后信念状态出发，而非栈弹出/流水线回退）
- 回溯全程落工件（`belief_state` 快照 + 决策记录），可审计、可复现

### 1.4 原则演化 + Taste 校准
- **原则演化**：异常累积检测器（同一假设空间内挑战证据密度超阈值）→ 触发 paradigm-shift 模式：放宽假设、生成新 claim 簇（PiEvo 异常驱动扩充的 Agent 化）
- **Evaluative taste 校准**：代理分模型（预测的论文质量分 vs 真实 7-lane 评审结果回归），每项目/每 venue 在线更新；让平台"品味"随时间逼近真实
- **Generative taste**：新 idea 新颖性打分 = 与文献图嵌入距离 + claim 图去重

**验收**：三份样例课题（idea→实验→论文骨架）跑通信念闭环；回溯产生完整工件链；校准曲线随评审轮次收敛。

## Phase 2 — 科研感知路由（Research-Cognizant Routing）

### 2.1 确定性能力需求路由
请求构建时静态推导所需能力（工具集、附件模态 image/pdf/audio、工件类型上下文）→ 过滤候选模型（替代现在"先选后查媒体再静默换"的滞后路径）

### 2.2 摊销学习排序 + 不确定性门控 judge
- 新增 `src/router/learning/`：**在线学习的轻量排序器**（特征：任务类型、工具集、工件类型、历史结果、成本），从每次路由结果（成本/延迟/是否出错/用户反馈）在线更新 —— 每项目个性化
- judge LLM 只在排序器置信度低时调用（把每轮 5-15s judge 延迟降为偶发）；短续接/粘性命中走快速路径

### 2.3 工件感知分层 + 级联质量估计
- 工件类型→tier 先验（figure_table 渲染→多模态；experiment_analysis→reasoning；写作→写作型模型）
- 2026 级联趋势：弱模型先出，质量估计器低分→升级强模型重跑（在 tool 结果层而非单 token 层做）

### 2.4 与编排引擎一体化
- EIG 规划器输出动作类型 → 路由先验输入；路由失败/降级 → 反馈回 claim 图的代价模型（同一学习回路）
- 粘性 TTL + 退化释放（Phase 0.3 落地）

**验收**：judge 调用率下降 ≥50% 且质量不降（对照 stats.json）；路由决策事件含能力需求依据；失败回退路径有测试覆盖。

## Phase 3 — PaperStudio 论文工坊

### 3.1 目标 venue 前置敲定（科研启动即定模板）
- `src/research/direction/` 扩展：方向探索阶段即采集 `targetVenue`（用户选择或推荐），写入 ResearchBrief
- **模板服务** `src/research/manuscript/templates/`：按 venue 自动下载模板（ICLR 2027 官方未发则取 2026 改年份），复用现有 `template_probe` + commit 钉扎机制，扩展为多 venue 注册表（ICLR/ICML/NeurIPS/ACL/期刊…）

### 3.2 Venue 范文语料 + 细粒度风格学习（每项目独立）
- **范文采集**：开题时下载目标 venue 近两年 Best Paper + 高分论文共 10 篇（文献层 OpenReview/arXiv/OpenAlex + PDF 获取，新增 artifact 种类 `venue_corpus`）
- **风格画像** `src/research/manuscript/style/`：细颗粒度分析——句子模板（首句/过渡/论证句）、段落结构（段首主张-证据-解释-衔接）、图表风格（配色/坐标轴/标注）、故事线（motivation→gap→method→ablation→implication 的节奏）、LaTeX 排版习惯、引用密度与位置
- 产出 `venue_style_profile` + `style_snippet` 工件；**每篇论文独立学习**（项目隔离不变：`<project>/.rigorium/research/`）
- **风格记忆**：学习结果写入项目记忆，随论文迭代实时更新（"当前项目记忆"）

### 3.3 视觉辅助子系统（原生，非 MCP 外挂）
- 在 `src/model/protocol/multimodal.ts` 的 `downgradeUnsupportedContent` 边界处接入：主模型无视觉时，图片自动交给视觉模型描述后注入上下文（Codex read-image 模式，但网关内原生实现，支持流式工具结果图）
- 配置面 `rigorium.yaml`: `vision: {provider, baseUrl, apiKey, model}` —— 兼容 GitHub Copilot（OpenAI 兼容端点）与任意 OpenAI 兼容服务；同时暴露 `describe_image` 工具供 OCR/图表理解显式调用
- 模型目录增加 `supportsVision` 能力标记

### 3.4 GPT Image 2 生图（配置面先行，标注待测）
- 新工具 `figure_generate`：输入规格（架构图/数据图类型、风格描述、尺寸）+ 配置面 `figureGen: {baseUrl, apiKey, model}`（**标注 README：待用户提供 Key 后测试**）
- 架构图等直接文生图（不经过 LaTeX）；数据图优先代码绘制（matplotlib 等），风格参数取自 3.2 风格画像
- 输出注册为 `figure_table` 工件（沿用现有 provenance 要求）

**验收**：开题→模板下载→10 篇范文入库→风格画像生成→论文写作引用风格画像；无视觉模型环境下图片经视觉辅助正常理解；figure_generate 配置面可保存/校验（不发真实请求）。

## Phase 4 — 平台整合 + 自举闭环

### 4.1 技能生态
- 导入学习：synthetic-sciences/OpenScience（250+ skill）、scdenney/open-science-skills 中高价值技能（按我们的合规校验器 `SkillManager.validate` 筛选导入）
- 技能市场入口：统一插件系统落地的 marketplace UI（git 安装）

### 4.2 平台级整合
- always-on/cron 接入 claim 图：候选监控升级为"主张监控"（文献出现挑战/支持证据时通知编排器）
- 记忆系统接入风格画像与信念快照（项目隔离保持）

### 4.3 自举论文（最终里程碑）
用平台完整走一遍：目标 venue（ICLR/ICML）→ 模板下载 → 10 篇范文风格学习 → 信念驱动编排完成实验/写作 → GPT Image 2 绘图 + 视觉辅助 → 7-lane 评审 → 修正。产出《Belief-Driven Orchestration: ...》框架论文 + 完整工件链。
- 评估：ResearchClawBench/AI Scientist 协议取样 + 内部路由成本曲线 + 评审分对比

### 4.4 论文与文档
- 撰写论文主体（创新点：信念驱动 EIG 编排、科研感知路由、能力注册表统一架构、taste 校准）
- 每阶段增量文档（沿用 docs/research/increment-*.md 风格）

## 实施原则
- 每阶段：先抽模块+测试护航 → 新功能 → 增量文档 → 阶段验收，全程保持 `npm test` 绿
- 破坏性重构（Phase 0.2 插件统一）做双轨兼容期：旧 manifest 自动迁移
- 外部依赖（GPT Image、视觉端点、范文 PDF）全部可配置、可 mock、标注待测，不阻塞开发
- 子代理并行推进独立模块（如 1.2 EIG 规划器与 3.3 视觉子系统无依赖，可并行）
